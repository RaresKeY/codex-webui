# Jev text-chat routing

Owners: `backend/app/chat_service.py`, `backend/app/task_router.py`, `backend/app/routing_policy.json`, the message routes in `main.py`, `frontend/src/api.ts::sendPrompt`, and ChatSurface/Composer in `App.tsx`.

The policy began as a source snapshot of `../jev-task-router/routing_policy.json` version `2026-10-05-v5` (source commit `1ee5700`). Luna executes established, documented, repeatable flows. Sol handles bespoke work, synthesis and foundation design; a new reusable workflow or initial visual baseline tends toward Sol high. Applying a known approach can still use Sol low. WebUI 2 now uses `2026-10-06-webui2-v8`: the user-directed quality preference treats Luna as generally lower quality and prefers Sol 6.1 for learning, teaching and how/why explanations, even when a question appears simple. Educational anchors distinguish simple low-effort explanations, medium teaching and difficult high-effort topics. This is a routing preference, not a measured capability claim; model strength and effort remain separate. The original task-router project and historical experiments are unchanged. Decision provenance uses the policy version sent in that Jev request.

The backend router makes one HTTPS call to `https://api.typesafe.ai/v1/systemone` with `model: jev-1.13.0`. State contains the original task and shared routing policy, without history, project files, identifiers or experimental labels. Five typed Choices ask for model, effort, online-search benefit, need for up-to-date external information, and project-context benefit. The three diagnostics each choose yes/no/unclear, independently of model and effort, including Luna low. They apply to every Auto classification and preview; manual sends still skip Jev. Shared policy appears once in state; contextMissing remains a legacy null field. Diagnostics are advisory: the service does not fetch web sources or project summaries automatically. Bounds cap the nonblank ask at 24 KB, serialized payload at 60 KB and reply at 128 KB. Validation checks whitespace without changing the submitted text. The request times out after 30 seconds and is not retried.

Validation requires the exact model, answer IDs/types, both allowed model choices, five effort choices, all three diagnostic choices, finite probability values summing within 0.025 of one, Choice matching a maximum, finite confidence, and nonnegative integer usage. Invalid/missing/inconsistent answers fail closed. Safe output includes chosen model/effort, separate confidence, validated probability vectors, classifier usage, typed preparation answers, the legacy null field and policy version. Only whitelisted decision metadata is retained for [Jev activity](jev_activity.md); raw replies and prompts are not persisted or logged.

`POST /api/threads/{id}/messages` owns the complete send operation. `/turns` is a compatibility alias of the same handler. Accepted input is the exact ask plus optional validated approval/sandbox settings; caller model/effort fields and other unknown fields are rejected with 422. Thread creation only creates a thread and rejects `prompt`. Direct `turn/steer` projection returns 409 so follow-up asks use the routed operation after the current turn finishes. `/route` remains a non-executing classification preview; its result is never accepted as authorization to skip routing.

Auto is the default for new and existing chats. A per-chat speed menu can explicitly save a manual model (`gpt-6.1-sol` or `gpt-6-luna`) and effort (`low`, `medium`, `high`, `xhigh`, `max`) through GET/PATCH `/execution`. Manual settings changes use the same thread lease, reject active turns and require native acknowledgement before saving. Returning to Auto saves that choice without model execution. Manual sends skip Jev, bind the saved model/effort with native acknowledgement and submit the unchanged ask; their decision has `policy: manual`. The Luna elevated-effort review barrier remains specific to automatic decisions. Unknown saved selections fail closed. Direct message-body model/effort overrides remain rejected.

Before spending in Auto, the backend confirms Codex availability and thread metadata, and rejects incompatible paginated history or an active turn. In Auto it then awaits Jev selection → `thread/settings/update` acknowledgement → `turn/start` with the unchanged ask and matching model/effort. `thread/loaded/list` determines whether a single `thread/resume` is needed before the settings update. Fresh loaded threads receive a real settings update without provisional-resume fallback. Only the installed protocol's empty-object settings response counts as acknowledgement; metadata never substitutes for a model change. Neither model change nor ask submission occurs after a routing error; ask submission does not occur after a loading/model-change error. Luna high/xhigh/max stops submission independently of browser checks. New chats explicitly use legacy Codex history. No stored history or global Codex configuration is changed.

Ordinary clients receive a JSON result with `decision`, `turn` and `modelChangeAcknowledged: true`, or an HTTP error. The browser uses one request with `Accept: application/x-ndjson`. The stream emits routing/switching/sending stages followed by either that result or a bounded error frame containing its status and message. The stream's initial 201 is transport status, not proof of successful submission; the browser requires a valid terminal result and treats an error/truncated stream as failure.

A backend per-thread lease prevents overlapping sends and competing public model changes within this process; a synchronous composer guard also prevents double clicks. Failed drafts stay editable and preserve their exact whitespace; no hidden retry is made. Changing chats cancels the pending HTTP operation; cancellation observed before the next stage stops further submission. An already dispatched turn remains Codex-owned. Native turn notifications remain authoritative after submission. The browser registers its pending request before opening the stream, so delayed progress cannot reset an already completed turn. A `webui/modelSelected` notification shares the ordered thread socket before turn dispatch, preserving model provenance even if WebSocket events arrive before HTTP progress. After routing, the header shows the latest chosen model and effort together (for example, `6.1-sol · high`) on desktop and phones; assistant messages keep per-message model provenance.

Credentials are read directly from JEV_API/TYPESAFE_API_KEY environment or the configured external file, never sourced as shell code or copied into frontend/image layers. The container launcher mounts `../jev-pipelines/.env` read-only when present. Keys and provider error bodies are never returned to the browser.

Verification: `backend/tests/test_task_router.py` checks strict validation, input isolation, credential precedence, one transport call, safe errors and zero Codex calls from standalone classification. `backend/tests/test_routed_chat.py` checks both direct submission URLs, bypass rejection, real-ack barriers, exact padded Unicode input, loading, cancellation/concurrency and streamed failures. `frontend/src/routed-send.test.ts` checks the single streamed request, decision/result validation, cancellation and model provenance. `tools/check_browser.py` verifies the composer sends exact padded text once; `tools/check_thread_lifecycle.py` exercises native settings acknowledgements on fresh threads with only paid transports replaced by fixtures. Tests do not spend inference calls.

The WebUI learning-policy update passed 143 backend tests, 75 frontend tests and the native offline lifecycle check. The updated container is healthy on loopback and private HTTPS. Actual paid Jev classification was not exercised; these tests verify the transmitted policy and provenance, not a measured classification success rate.

The V7 refinement explicitly anchors bare greetings, thanks and simple social exchanges to Luna/low, with or without a selected project. Teaching and substantive-work requests keep the Sol quality preference. Workspace selection is not supplied to Jev and must not inflate the immediate ask. Mocked backend submissions verify exactly the same padded greeting reaches routing and execution with/without a workspace; no paid classification comparison is implied.

## Gaps

- No paid Jev/Codex end-to-end smoke has been run here.
- No project brief or conversation context is supplied; follow-up estimates can have missing context.
- Search/freshness and project-context questions are advisory; actual preparation and maintained summaries remain TODO/research in [turn_preparation.md](../design/turn_preparation.md).
- Independent model and effort predictions are not a joint distribution or measured task success.
- Schedules and realtime voice retain inherited execution paths.
